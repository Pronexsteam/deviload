# Playback and download improvements in development

This package is being prepared together for the next release. It does not change the application version or the release workflows.

- Music volume uses a squared slider curve for finer control near silence. Existing saved volume remains the same physical output level; the displayed percentage reflects the new control position. Mute restores the previous nonzero level.
- Download settings show the audio languages and exact audio tracks reported by the source, plus manual and automatic subtitle languages. Language preferences travel with saved profiles, settings backups and subscriptions. Exact stream IDs and size estimates belong only to the checked link. An unavailable selected track is reported rather than silently replaced.
- Preflight shows known source bytes, queued bytes on the destination disk, a conservative working-space budget and the number of items with unknown size. It does not scan an entire remote playlist. Output sizes after conversion and live recording remain unknown.
- Devil Cut offers a lossless trim for one unmodified clip. It copies compatible original streams into a separate file and shows requested versus keyframe-aligned boundaries. Effects, extra audio and multi-clip timelines still use the normal rendered export. The saved file is checked before publication; cancellation removes the partial result.
- Playback reports contain bounded recent stage, error-category and timing information plus engine version/status. Track names, links, paths and account data are excluded. Reports are exported only on request and are never uploaded automatically.
- Local recommendations balance evidence across artists, account for collaborations and recent playback across radio batches, reserve room for unfamiliar artists and explain the observed reason for each personal recommendation. Muted playback, seeks, paused time and private listening do not add positive taste evidence. Likes, exclusions, modes and existing v1 profiles remain compatible. Manual queues are not reranked.

## Contextual recommendations

Starting a collection or mood/search selection gives radio a bounded set of representative tracks from that selection. The current track and another representative can drive continuation rather than always adding an unrelated global favorite. Candidate source and original rank contribute bounded evidence; this is not an inferred genre or acoustic model. Network fan-out stays bounded, and successful raw radio pools remain reusable.

Prepared radio candidates are ranked against the current mode, favorites, exclusions and session immediately before they enter automatic playback. Changing familiar/discovery mode does not replace or reorder a manual queue. Historical familiarity is separate from decaying positive interest, so a retained, qualified artist does not become a new discovery merely because their score faded.

Selecting another search result or queue item does not create a durable dislike. An early Next on an automatically recommended track adds temporary, exact-track fatigue; repeated distinct skips pause that track for 20 minutes, including when it remains liked. Qualified listening clears that temporary skip state. Explicit hidden songs and blocked artists still take precedence. Legacy negative evidence remains readable.

Only recommendation cards visible for at least half a second in a focused music view count toward temporary exposure rotation. Ignoring a card does not create a dislike. Failed sources receive a short availability pause, separate from taste, and manual retry remains available. This session state is bounded (40 context tracks, 500 impressions, 200 skip records and 200 availability records) and is not exported or persisted. Entering or leaving private mode clears it.

Imported playlists still provide a weak, opt-in cold-start prior. Undated imports retain an unknown last-played date; dated listening decays from its supplied date. Imported evidence uses available history slots and does not overwrite or evict existing learned taste, including negative evidence. Library likes, playlist membership and the existing 2 MiB profile limit are preserved.

Recommendation candidates still come from the guest music catalog. These changes improve local selection; they do not reproduce YouTube's private server model or guarantee that every source track can play.

## Personal interest mixes and recording choices

The library can save up to eight named interest mixes, each referencing up to eight existing playlists. Opening a mix combines its source tracks with at most three representative source radios. Familiar/discovery changes rerank the retained raw pool without another catalog request. Positive preferences stay within that interest, while global hidden tracks, blocked artists and temporary availability/skip rules still apply. Global familiarity remains accurate in discovery explanations.

A mix can retain up to 100 track references learned from qualified audible listening within that mix. Unrelated manual queue entries and private listening do not train it. These references reuse existing bounded taste metadata; they do not create another listening log. Deleting a mix leaves its source playlists intact. Configurations and explicit recording choices travel with the existing v2 profile and backups; old v1/v2 backups still load with safe defaults and the 2 MiB limit is unchanged.

Choose track version opens a source search with title, artist credits, duration and recording differences. Slowed, sped-up, live, cover, named remix and remaster details remain distinct. Strong metadata agreement is only a suggestion, not proof of identical audio. Nothing is automatically rebound or merged. Selecting a source preserves the logical song in likes, history and playlists, and routes playback, preloading, available offline playback and new MP3 downloads to that source. Use original source reverses the choice.

Only explicitly confirmed source relationships deduplicate recommendation candidates. Their cooldown, exclusions and temporary failures apply across aliases without multiplying listening evidence. Manual queue entries remain under user control. There are at most 200 source choices; metadata excludes stream addresses, file paths and credentials. Restoring a profile discards any pending audio resolution for a replaced source and preserves a paused player's state. Resuming a mix retains its interest context; private-mode and profile resets clear that temporary context.

## Public ListenBrainz discoveries without an account

An optional, default-enabled discovery source adds public ListenBrainz artist/tag radio candidates to the existing local ranking. No account, shared token, user identifier, scrobbles or history upload is used. Requests contain up to two artist names and two allowlisted genre tags; ListenBrainz and MusicBrainz can see those queries and the connection's IP address. The setting can be disabled, survives profile export/import, and is disabled at runtime for private sessions, offline devices and data-saving connections.

Existing home, interest and autoplay results remain usable while enrichment runs in the background. Interest requests use their own source tracks; autoplay uses its selected listening context. A new profile without preferences can receive a public pop starter shelf labeled Explore with ListenBrainz rather than a claim of personal relevance. Saved local taste, current mode, hidden songs, artist exclusions, recording aliases and temporary session gates still decide the final ranking. Late replies cannot change another view or a private/disabled session, and cannot replace an active or manual queue.

Public MusicBrainz artist IDs are resolved conservatively. The provider retains complete artist credits and recording disambiguation, including version details. At most three catalog searches per augmentation resolve a rotating subset of up to twelve metadata candidates; only exact normalized title, complete artist/version agreement and a finite close duration are accepted. Unknown or ambiguous versions are skipped. No source bindings are created automatically. MusicBrainz remains the metadata authority because the public ListenBrainz metadata cache omits recording disambiguation.

The native client uses fixed HTTPS endpoints, no redirects, the existing proxy, a contact User-Agent, at least one second between requests per host, rate-limit backoff, a 1 MiB response limit and an 18-second operation budget. It retains at most 64 public response entries in memory; resolved candidates use a separate 24-key transient cache. Successful resolved lists expire after one hour, genuine empty results after ten minutes, while incomplete/retryable results are not retained by the resolver. Service outages, rate limits, missing metadata or missing playable matches leave the existing recommendation path available. Availability and recommendation quality are not guaranteed by the integration.
